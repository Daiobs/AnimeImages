# 统一管线：按平台切换（契约第 3 步）

契约见 [unified-pipeline.md](architecture/unified-pipeline.md)。本页记录切换开关怎么用、切换后用户看到什么、已知限制。

## 开关

- 后台 → `统一管线路由`（`/admin/xhs_download/pipelineroute/`），每个平台一行，行由迁移写入。
- `使用统一管线` 打开后，该平台的新解析走统一管线；关闭后立即回到原路径，已经发出的选择器也随之失效（需要重新解析）。
- 读不到这张表（例如代码先于迁移上线）按“关闭”处理。
- 目前抖音、小红书和 B 站有统一实现；其他平台的行即使打开也不生效。

抖音的默认路由（迁移 0033，默认关闭）：

| 配置 | 值 |
|---|---|
| 顺序 | 天天解析 → KuKuTool → Native |
| 策略 | `floor_and_upgrade`，保底 Native |
| 前台预算 / 升级窗口 | 8 秒 / 8 秒 |
| 冷却 | 基础 10 秒，按连续失败翻倍，上限 300 秒；每个进程各自计算，成功一次清零。只有服务不可用才冷却；天天对某个作品返回业务码 1（没有媒体）不冷却 |

- 天天和 KuKuTool 只在用户可用原画/超清时参与，照旧扣每分钟额度；KuKuTool 需要配置 sidecar。
- Native 从一开始并行运行，拿到整个窗口。
- 首选在升级窗口内成功，就展示首选的结果；首选都失败，或窗口结束时首选仍没有结果，就展示 Native。页面等到结果确定才返回，不会先展示 Native 再升级。

小红书的默认路由（迁移 0034，默认关闭）与抖音相同：天天解析 → KuKuTool → Native，Native 保底，预算和窗口都是 8 秒。服务 Provider 只在现有小红书路径会调用它们的地方运行：

- Native 每个请求只读一次笔记页面，保底和服务准入共用这一次的结果；
- 天天只为可用原画/超清的请求增强普通视频笔记（一条视频，没有图片和实况），并照旧扣每分钟额度；图文笔记不调用天天；
- Native 没有结果时，后台第三方准入允许的服务（KuKuTool、天天）才作为兜底运行；
- 天天返回的标题必须与 Native 的标题对应，否则不采用。

小红书实况的保存方式由同一行的 `实况保存方式` 决定（迁移 0036，默认“实况照片”）：

| 选项 | 页面 | 下载 |
|---|---|---|
| 实况照片（默认） | 每张实况一张卡片：照片带“实况”角标，可预览动态 | 单张：浏览器打包 `基础名_序号_livephoto.zip`（照片和动态）；多选或全选：一个 ZIP，实况各占一个文件夹 |
| 照片和视频分开 | 照片卡片，动态作为视频卡片，与照片同序号 | 单个动态按视频保存；图片和视频一起选时，浏览器打成一个 ZIP |
| 只保存照片 | 只有照片卡片 | 原图 |

- 实况照片沿用现有的实况功能（卡片、预览、配对下载、浏览器打包），对所有访客开放；令牌只给生成页面的那个浏览器用，30 分钟内有效，不超过 CDN 链接的过期时间。
- 配对只来自 Native：同一 imageList 项的照片和动态。照片取原图 JPEG，动态取 h264 流，主机须是实况功能验证过的 `sns-video-vN` 或 `sns-bak-vN`。不满足时整条笔记按“照片和视频分开”展示，所有文件仍可下载。
- 天天兜底的结果没有配对信息，同样按“照片和视频分开”展示。
- 下载全程由浏览器读取 CDN，服务器不转发媒体。

B 站的默认路由（迁移 0035，默认关闭）：Native → 天天解析，`first_success`，预算 8 秒。

- Native 的 playurl 一次只给一种清晰度，并列出当前匿名环境能给的其他清晰度（`accept_quality`）。统一管线在同一环境里逐个再要一次，每种最多一次、最多 3 种，遇到错误就停（不重试）。匿名环境一般是 720P 和 360P 两种完整 MP4。
- 1080P 及以上需要登录或服务端合并独立的音视频轨，不在浏览器下载范围内，不列出。
- 天天保持现有的可用性兜底：只在 Native 没有结果时、只对第一个分 P、只对后台第三方准入允许的请求运行，运行时才扣现有额度。

## 用户看到什么

- **图文：** 与原来一样的图片卡片，可自由选择，下载原图。
  - 小红书原图按现有规则（`normalize_xhs_image_url`）取全尺寸 JPEG，不再是页面里的 1080 像素 WEBP。
  - 小红书实况照片：按后台的“实况保存方式”展示，默认是实况照片卡片（见上）。
- **视频：** “选择清晰度”列出展示结果的全部清晰度。
  - 同一文件的多个镜像只列一次；
  - 抖音带水印的 `download_addr` 不列出；
  - 默认选最好的一档（原画优先，其次分辨率、码率）。
- **下载：** 点下载时，服务端只请求每个镜像的第一个字节，挑出浏览器能跨域读取（CORS）的镜像，返回一个普通视频条目。浏览器经现有 Service Worker 流式保存，失败退回浏览器整块保存。服务端不转交正文。
  - 服务端在时限内没等到某个镜像的回应（超时、连接失败）时，这个镜像算“未知”，交给浏览器自己尝试，不再直接报“无法读取”。只有每个镜像都回应了且都不允许跨域读取时，才提示换一档清晰度。
- **提示：** 有清晰度选择器时也显示解析提示，例如请求原画但本次只取得普通清晰度。
- **技术信息（仅管理员）：** “查看技术信息与全部原始候选”列出本次链路（策略、展示的 Provider、每个 Provider 的结果和代码、用时），以及展示结果返回的每个链接：清晰度、格式、分辨率、大小、主机和未展示的原因。只显示主机，不显示链接。

## 已知限制

- 单独的音频（抖音原声）暂不提供下载：现有浏览器下载不支持非上游来源的单独音频。
- 天天不给大小时，页面显示“大小未知”，下载时按实际大小保存。
- 所有镜像都回应且都不允许跨域读取时，提示换一档清晰度。契约第 8 节第 1 条的“失败后改由服务器转交”尚未接入统一管线。
- 技术信息只列出被展示的 Provider 的链接；其他 Provider 只显示结果和代码。
- 选择器的引用 30 分钟内有效（不超过 CDN 链接的过期时间），过期后需要重新解析。
