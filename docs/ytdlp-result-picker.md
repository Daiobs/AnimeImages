# 用户结果与格式选择

本指南按 main 应用快照 `c2b8ac51cfb87d4c030d321bf763080708db9593` 描述当前首页与 Batch 的共享格式选择。文件名和组件命名沿用 yt-dlp，但已接通三类结果：

| 返回路径 | Provider 身份 | 操作与边界 |
| --- | --- | --- |
| 共享 yt-dlp | `yt_dlp_generic` | 真实格式与轨道事实，适用时按需检查所选 HTTPS MP4 |
| 通用服务 | `tiantianjiexi_generic`、`kukutool_generic` | 保留明确视频分组与上游标签，沿通用来源准入及原交付能力 |
| 抖音专用服务 | `tiantianjiexi`、`kukutool` | 保留 aweme 身份、逐资源 manifest 与成熟来源准入，不借用 generic 授权 |

没有共享候选、无法可靠关联的旧资产及多作品结果保持各自展示，不捏造格式列表。图片数量不等于视频档位；服务没有原生 format ID 时使用应用候选身份。格式选择不是 Staff 专属，但匿名是否获准仍由实际配置决定。

下方带日期的段落是阶段性验收，保留当时 Head、身份、配置、失败与 transport；当前说明不将早期 Blob 文件改称 SW 成功。#99/#100 已合并，生产状态见 [当前版本状态](current-version-status.md)。

## 用户流程

1. 展示来源 hostname、作品标题、作者、时长和所选文件大小。封面从当前已签发作品记录读取，可选封面失败不影响候选。
2. 视频优先；纯音频作品直接显示音频；视频作品的独立音频默认折叠。
3. 视频清晰度全部展开，原画和数字清晰度从高到低排列；桌面位于原视频预览右侧，窄屏上下排列。不同编码、帧率、语言或协议的同清晰度变体保留可区分的选项。音频原有次级折叠保持；大小估计明确标注，未知不补值。
4. 原作品标题、平台、资源数量、媒体勾选和顶部下载入口保留。默认选择及既有偏好不变；选择清晰度后，原下载按钮内部核验并保存当前候选，不再单独显示复制或旧方式下载按钮。Staff Batch 导出仍沿原权限使用当次选择快照。
5. 保留内嵌预览的路径只在明确点击后准备，播放器 `preload=none`；预览可选择较轻的完整格式，不改变下载选择。提供新标签页播放的路径会冻结并核验当前选择，再打开对应 CDN 视频，不切换勾选、不启动保存。弹窗拦截与源站访问失败分别提示。
6. 历史技术信息和全部原始候选仍可展开。HLS/DASH、分离轨、未知轨道、HTTP 和必要上下文结果不消失，但本次不会把它们伪装成完整可下载文件。

样式使用 DokiTool 蓝紫色与浅色背景，不替换站点品牌或引入 Vue/Electron。

## 实际接线

- `tools/upstream_match_worker.py` 在既有字节预算中保留可选 thumbnail；不会因装饰字段变化下载媒体。
- `normalize_upstream_result` 给单作品的首个候选绑定作品摘要和私有封面引用；排序后仍按实际持有作品信息的候选取摘要。
- `services/ytdlp_selection.py` 负责纯展示投影和可信缓存记录的所选文件描述，不运行提取器。
- `POST /media/ytdlp-selected-format/` 只接受候选 ID、短期资源 token 和动作。客户端不能发送媒体 URL、format selector 或轨道声明。每次重新检查当前 Provider/来源准入、CSRF、私有记录和既有下载限制。
- 服务结果通过 `service_format_selection.py` 与 `POST /media/service-selected-format/` 复用控制器，保留真实服务身份和原 manifest；不能用第一档授权保存其他档，也不因缺少可选 codec/fps 而禁用原本获准的服务文件。
- 浏览器直连描述符不签发任意服务器媒体资源、不代理媒体；准确绑定的 legacy 动作仅沿用原资源交付流程，不新增 Relay。未选格式、其他候选、已失效 token、额外 URL 字段不能替代所选内容。
- 下载复用现有 `AnimeImagesOrdinaryMediaDownload` 或准确绑定的原资源流程，传输资格来自实际访问条件和授权，不由 Provider/卡片名称强制 Blob。明确独立音频保留真实容器；未知 WebM 不猜成纯音频，图片仍使用原图片路径。
- 所选资源自动保存保留凭据省略、CORS、响应类型、文件大小、停滞和取消处理。符合原共用 SW 条件的视频使用其已有起始地址及终点检查；受限的 Blob 兼容路径仍拒绝重定向。新标签页/原生预览导航与 fetch 的保护不等价；可打开不等于可自动保存。失败不自动改用服务器，也不偷偷改成别的格式或纯音频。
- “已交给浏览器保存”不是磁盘保存的遥测证明。真实文件验收须检查浏览器下载和最终文件。

## 刻意没有扩大

本次不启用原生 GenericIE、JS Runtime、Cookie 读取、浏览器自动提取或新来源公开权限；这些需要独立的运行能力验证，不应借界面变化直接放开。既有成熟/旧版 `YtDlpResultNormalizer` 路径没有可用共享候选时继续使用原界面，不伪造格式列表。

本次没有服务器合流、HLS 分片下载、转码或无损升级。只有完整 HTTPS 视频和明确的独立音频适用现有浏览器保存；来源 CORS/HTTP 条件仍可能失败。原封面需要上下文或不能跨域时保留占位信息，不新增图片中转。

## Worker 更新与下载确认

选择与传输分层：正常动作接口验证所选候选及 manifest，页面冻结响应，并在移交前再次检查有效期。Worker 只接收传输 ID、URL、文件名、预期字节、创建时间和准备期限，不接收候选 token、Provider 或 manifest。保留旧绑定消息处理仅为兼容已经打开的旧页面。

新页面直接复用实际 controller 的原有普通视频注册/导航接口，不以业务协议版本完全相等为门槛，不要求等待全部下载、关闭所有标签或强制替换 Worker。旧 v2 控制页面、新 v4 waiting 时也可传输；现有任务不因启动新任务而取消。注册结果未知不重发，已经开始的下载不自动切成 Blob 或服务器下载。

授权与传输期限不混同：过期候选不能签发或移交新任务；已经获准移交的任务沿用普通下载最长 120 秒的准备窗口，而不是延长原候选缓存/token。窗口到期未开始则拒绝；已开始的流不因候选到期中止。普通 SW 视频统一沿用原有 2 GiB 字节上限及已审查 CDN 终点规则，不再仅因存在选择身份改成 1 GiB 或禁止一切重定向。Blob 内存兼容路径仍保留其 1 GiB 上限；来源准入、用户配额、TLS、MIME 和授权接口不变。

文件名在移交下载前确定：已有资源文件名及明确扩展名优先保留；抖音专用入口原本获准下载的完整视频，在上游未提供扩展名时沿用原下载入口的 `.mp4` 命名默认值，不再由选择器的 `.bin` 覆盖。该默认值不是容器或音轨探测结论，也不应用于未知通用资源、音频或流媒体。新版 Worker 仍可根据可信响应 MIME 补齐未知后缀，但正常命名不要求旧用户先升级 Worker。

[Chrome 的真实流式记录](https://github.com/Daiobs/AnimeImages/pull/100#issuecomment-6251827401)对应 `58f79d57` 的日常抖音专用天天 720p；[Safari 的升级与保存记录](https://github.com/Daiobs/AnimeImages/pull/100#issuecomment-6252702886)对应 `e7c9d9f` 的原日常会话。两者均有浏览器任务先于流结束和实际文件证据，不是仅握手成功。应用内浏览器的首块取消仍有环境原因缺口，不能用正常浏览器结果替代。未单独声明的身份不补写为匿名。

下载按钮不会主动打开视频；浏览器“下载后打开”的自身偏好与应用播放操作分开。页面完成回调不单独证明文件落盘。

### Shared transport precedence

Provider identity and card/selection identity describe provenance and authority,
not a transport override. After normal action authorization, complete videos in
the existing reviewed SW resource scope prefer streaming, including old resource
cards and selected formats. Obsolete `forceBlob` hints cannot override this rule.
The backend strategy, authorized action descriptor and shared frontend entry use
the same precedence. Existing authorization contracts remain distinct and checked.

Legacy upstream resource cards retain their exact manifest, work/cache identity
and original resource expiry under `upstream_resource_v1`; no candidate identity
is invented. Old cached records without that expiry require a fresh normal result
for this path, not a fabricated extension or automatic Provider request. Protocol
4 prevents an older Worker from treating the new binding as an unbound resource.

their existing bounded browser compatibility path. Necessary context, streaming
media/separate tracks, expired authorization and unsafe URLs do not gain delivery
permission. No new Provider-specific streaming exception or domain admission is
introduced. Controlled slow-stream evidence is separate from live file evidence.
